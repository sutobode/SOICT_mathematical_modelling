In addition, the patch adds:

- **Time-budget guard** (`orange/src/experiment.jl`):
  - The budget is measured with Julia's monotonic clock.
  - A HiGHS callback records the last improving solution and the last dual bound reported **within** the budget, and asks HiGHS to stop once the budget is exhausted.
  - If HiGHS still overruns by more than 10 s, inside a phase that calls no callback, the run reports the state at the budget, with `check = ok(budget-truncated)` and time = limit.
  - Each run writes `*-budget.json` as evidence.
- **Status aggregation** (`orange/src/reporting.jl`, `orange/scripts/official_common.jl`, `official_tables.jl`):
  - Labels: `Optimal` / `Feasible - not proven optimal` / `Restricted feasible upper bound`.
  - When runs tie on MLU, a proven-optimal run is preferred.
  - Restricted rows show `N/A (restricted)` in the optimal-runs column.

## 3. Baseline definition

`base_mlu(inst, rs, P) = max_utilization(inst, rs, direct_paths(inst, P), P)` (`orange/src/verify.jl:27`), with `rs = [build_r(inst, p; mode=:pathcount) for p in 1:P]`.

- Every demand uses only its own segment ⟨s_d, t_d⟩ in every period.
- Segment traffic is split with the course's path-count coefficients `r = σ_ixσ_yj/σ_ij` (`calculating_r.pdf`) on the shortest-path DAG of G_p.
- G_p excludes the links taken down in period p.
- For P=2, the value is the maximum over both periods.

> **MLU_base = max_p max_{a∈A_p} Σ_d vol_{d,p} · r^p_{s_d t_d}(a) / c_a**

Improvement = (MLU_base − MLU) / MLU_base × 100.

## 9. Known limitations

- **Patch not committed.** The rerun ran on 0da1a52 + an uncommitted patch (hash recorded above). Commit it so the code version of the final tables is traceable in git.
- **Split coefficients.** These follow the course's `calculating_r.pdf` (path-count). They differ from the per-node ECMP split described in the challenge text when the branches of a shortest-path DAG carry different numbers of paths.
- **Objective.** It is pure MLU, the first term of the challenge's lexicographic objective (5). Exact lexicographic optimisation (`exact_lexicographic_loads!`) is implemented and tested, but it was not part of this campaign.
- **The MILP mostly certified the heuristic start.** In 100 of the 100 full-arc runs, the reported incumbent is the heuristic MIP start (`local_search`, seed 1). Within the budget, the MILP contributed the lower bound or the optimality proof, never a better routing.
- **Restricted model.** Its results bound the original optimum only from above; its gaps refer to the restricted model.
- **Shared VM.** The experiments ran in a VMware VM on a shared server; CPU contention was not measured.
- **Scale.** Only setA-01..05 fit the full model (≤ 2.97 M columns); scalability conclusions are limited to that range.

## 10. Post-campaign analysis (not part of the official runs)

SetA-05 P2 was later solved to proven optimality: MLU **0.2049858752**, versus the official 0.999986144. The proof is a node-cut argument and does not depend on the solver. The official MILP runs missed this solution because the `local_search` MIP start could not move under κ = 1. The heuristic has since been fixed. The official tables are unchanged. See `setA05_P2_supplementary_analysis.md`.
