In addition, the patch adds:

- **Time-budget guard** (`orange/src/experiment.jl`):
  - The budget is measured with Julia's monotonic clock.
  - A HiGHS callback records the last improving solution and the last dual bound reported **within** the budget, and asks HiGHS to stop once the budget is exhausted.
  - If HiGHS still overruns by more than 10 s, inside a phase that calls no callback, the run reports the state at the budget, with `check = ok(budget-truncated)` and time = limit.
  - Each run writes `*-budget.json` as evidence.
- **Status aggregation** (`orange/src/reporting.jl`, `orange/scripts/official_common.jl`, `official_tables.jl`):
  - Labels: `Optimal` / `Feasible - not proven optimal` / `Restricted feasible upper bound`.
  - When runs tie on MLU, a proven-optimal run is preferred.
  - Restricted rows show `N/A (restricted)` in the optimal-runs column.

## 3. Baseline definition

`base_mlu(inst, rs, P) = max_utilization(inst, rs, direct_paths(inst, P), P)` (`orange/src/verify.jl:27`), with `rs = [build_r(inst, p; mode=:pathcount) for p in 1:P]`.

- Every demand uses only its own segment ⟨s_d, t_d⟩ in every period.
- Segment traffic is split with the course's path-count coefficients `r = σ_ixσ_yj/σ_ij` (`calculating_r.pdf`) on the shortest-path DAG of G_p.
- G_p excludes the links taken down in period p.
- For P=2, the value is the maximum over both periods.

> **MLU_base = max_p max_{a∈A_p} Σ_d vol_{d,p} · r^p_{s_d t_d}(a) / c_a**

Improvement = (MLU_base − MLU) / MLU_base × 100.

Notes:
- **Single solver attempt.** Every full-arc run made one solver attempt (no acyclic retry), so retry budget sharing and node accumulation were not exercised. Both behaviours are covered by tests.
- **No clock jump.** The earlier solver-clock jump (setA-04 P2, first campaign) did not recur; all 10 reruns of setA-04 P2 ran 3602–3969 s by the monotonic clock.
- **What the overrun was (V3).** In the V3 setA-05 P2 overruns the solver logs show a silent phase from about 130–180 s to about 6300–6800 s, ending with a central-rounding (`C`) incumbent. This matches HiGHS computing the analytic centre with IPM on a separate instance, which honours neither the time limit nor callbacks. That incumbent was **not** used, because it was found after the budget. In the V4 runs the overrun is at most 26 s.
- **Seed dependence (V4).** With the same model and the same optimal MIP start, the root LP (dual simplex, presolve off) finishes in 1,665 iterations with seed 2 but is unfinished after 32,146 iterations with seed 1. The seeds that prove optimality in V4 (2, 3, 6, 7, 10) are exactly those whose V3 runs reached the bound 0.2049858752 after the budget.

## 9. Known limitations

- **Mixed code versions.** Rows come from three code versions (see §1). The local_search fix only changes the MIP start. It could improve other P=2 configurations as well, but only setA-05 P2 (budget 1 < 3, where the old heuristic could not move at all) was rerun.
- **Parallel processes in V4.** Running 5 processes at once may slow each run somewhat compared with the one-process-at-a-time runs. This is a conservative effect on setA-05 P2 runtimes.
- **Split coefficients.** These follow the course's `calculating_r.pdf` (path-count). They differ from the per-node ECMP split described in the challenge text when the branches of a shortest-path DAG carry different numbers of paths.
- **Objective.** It is pure MLU, the first term of the challenge's lexicographic objective (5). Exact lexicographic optimisation (`exact_lexicographic_loads!`) is implemented and tested, but it was not part of this campaign.
- **The MILP mostly certified the heuristic start.** In 100 of the 100 full-arc runs, the reported incumbent is the heuristic MIP start (`local_search`, seed 1). Within the budget, the MILP contributed the lower bound or the optimality proof, never a better routing. For the three V4 runs whose `incumbent_found_at_s` is 12.7–14.6 s, that time is when the guard callback recorded the incumbent, which is again the MIP start.
- **Restricted model.** Its results bound the original optimum only from above; its gaps refer to the restricted model.
- **Shared VM.** The experiments ran in a VMware VM on a shared server; CPU contention was not measured.
- **Scale.** Only setA-01..05 fit the full model (≤ 2.97 M columns); scalability conclusions are limited to that range.

## 10. SetA-05 P2: analysis behind the V4 rerun

The V3 runs stayed at the baseline 0.999986144 because the `local_search` MIP start could not move under κ = 1. A routing-independent node-cut argument shows that 0.2049858752 is optimal. After the heuristic was fixed, the official V4 rerun reached this value in every run and proved it in 5 of 10. See `setA05_P2_supplementary_analysis.md`.
